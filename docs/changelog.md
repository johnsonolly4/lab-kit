# Lab notebook kit: changelog

## Unreleased
- **To-do board: done to-dos go last in each column, then by priority** (planning kit, To-do board file): the board is sorted on `done` and then `priority` (1, 2, 3, none). Review update… offers it; if you edited your board it asks first (Keep keeps yours)
- **Plan map: shorter arrows** (planning kit): a card with nothing before it now sits just before its earliest child instead of at the far left, so its arrow no longer runs across the whole map
- **Subtasks in the project plan** (planning kit, theme, Vault spec): a to-do with `sub: "[[Parent to-do]]"` (typed by hand) is a subtask of that parent. On the plan map the parent's card shows `▸ 1/2`; click it to open a list of its subtasks, each with a tick circle and its name (click opens it). When every subtask is done the count shows `✓` but the parent is not ticked for you. Subtasks are not cards on the map; they stay ordinary to-dos on the board and may have their own `after`. A `sub` that names a missing to-do, itself, a loop or another subtask is ignored and a line under the plan says so (subtasks go one level only)
- **New command: Link to-dos in order** (planning kit, Cmd+P): select a list of `[[to-do]]` links in any note (a bullet list is fine) and run it; each to-do then comes after the one before it (`after` is written). It shows what will be written first and leaves out pairs that are already linked or would make a loop; the to-dos must all be in one project. A notice afterwards has Undo. No hotkey
- **Plan: blocked follows the whole chain** (planning kit): a to-do stays blocked while any to-do before it, however far back, is open, even if the one directly before it was ticked out of order. Ticking in a different order is still allowed. Dragging a link on the plan map also scrolls the map sideways by itself near its left and right edges, and the drag dot sits on the card's edge
- **Plan map: link and unlink by dragging** (planning kit, theme): hover a card (or a row in **Not linked**) and a dot appears; drag from it onto another card or row and that to-do now comes after this one (its `after` is written). Click an arrow, then **Remove link**, to remove one. Both show a notice with **Undo**. A link that would make a loop, or that exists already, is refused with a notice. Esc cancels a drag. Needs the theme update (Review update…)
- **Project hub: an Experiments tile** (planning kit, Project hub template, `show: project-experiments`): lists the lab notes that the project's to-dos name in `experiment`, each once, with its Status badge and the to-do that names it (`· 2 to-dos` when several). Started and Processing results come first, Closed last. Nothing is written to the lab notes. An old hub gets the tile through Review update… and Tidy up notes → Hubs. Needs the Lab folder set
- **A to-do can name its experiment** (planning kit, Vault spec): type `experiment: "[[ABC0014-A]]"` on a to-do (one link to a lab note). The plan map card and the Plan list show that lab note's Status (Planned, Started, Processing results, Closed) as a coloured badge, and on the map card a row shows the status and the lab note's name; clicking the row opens the lab note. It only displays: a Closed experiment does not tick the to-do or unblock anything. A link to something that is not a lab note shows a line under the plan. Needs the Lab folder set (Settings → Lab Kit)
- **Project hub: a card map of the plan** (planning kit, Project hub template, `show: project-map`, setting Project plan view): to-dos that come after each other are drawn as cards left to right joined by arrows (title, due date, priority, `→ result`; finished ones faded, blocked ones dashed). Click opens the to-do (Ctrl / Cmd-click: new tab), a circle on each card ticks and unticks it at once (open to-dos have a solid accent border, blocked ones a thick dashed one; the map scrolls to the next open to-do on opening) (so a wrong tick can be undone; right-click has Mark done / Mark not done too), hovering marks everything before and after it, and to-dos with no links are listed beside the map. The map replaces the Plan list; Settings → Lab Kit → Project plan view can keep both. An old hub gets the map through Review update… (template, theme) and Tidy up notes → Hubs, and keeps its list until then
- **Plan tile warns when dates disagree** (planning kit): an open to-do whose `due` is earlier than the `due` of an open to-do it comes after gets a line under the Plan tile (`"B" is due …, before "A" (…), which it comes after.`). Only dates you typed are compared; nothing is worked out
- **New to-do asks "Comes after?"** (planning kit, To-do template): for a to-do made for a project that has other open to-dos, one pick of those to-dos ("(nothing)" first) writes `after: "[[Name]]"`, so it shows in the hub's Plan tile as blocked until that one is done. Nothing is asked for a to-do without a project or a project with no open to-dos, and no `after` key is written when nothing is picked. Esc on this pick means nothing (it does not cancel the to-do, unlike the other boxes). For a second earlier to-do, type `after` by hand as a list. Review update\u2026 for the To-do template. Tests only, not seen in Obsidian
- **Project hub: a Plan tile** (planning kit, Project hub template, `show: project-plan`): under the hub's top row, the project's next steps first (open to-dos with nothing before them left open), then the blocked ones marked `after <to-do>`, then the finished ones with `→ result`; finished ones show with **Show all**. Nothing is drawn when no to-do of the project has `after` or `order` (a wrong `after` link still shows its message). Type `after` (a link to the to-do that comes first), `order` and `result` by hand in a to-do's properties for now. Review update… for the Project hub template and the theme; an existing hub gets the tile through Tidy up notes → Hubs: bring the page up to the current template (ticked by you). Tests only, not seen in Obsidian
- **Archive old to-dos keeps a project's to-dos** (planning kit): a finished to-do whose `project` hub is not Done is no longer archived after 30 days (the project plan will read it). When the project is Done, or the link finds no hub, it is archived as before. Also in the code, not yet shown anywhere: the project plan engine (`src/planning/plan.ts`) that reads `after`, `result` and `order`.
- **To-dos get a `priority` property** (planning kit, To-do template, Vault spec): empty by default; type `1`, `2` or `3` (1 = highest; set the property type to Number). In a project hub's To-dos tile and cards, to-dos are ordered overdue, then day (Mon to Fri, Backlog), then priority (1 first, empty last), then name. New to-do asks for it with a pick (No priority, 1 - high, 2 - medium, 3 - low) and sets the property to a number; Esc cancels. The to-do board order is unchanged (sort it with the board's Sort control on `priority`: 1, 2, 3 seen working by the user 2026-10-12).
- **New to-do: type the due date in words** (planning kit, To-do template): the due-date box now also takes `today`, `tomorrow`, a weekday (`mon`, `tues`, `friday`) and `next <weekday>`, and writes the date. Weeks start on Monday: `fri` is this week's Friday (today counts, otherwise next week's) and `next fri` is the Friday of next week; `YYYY-MM-DD` still works. Review update… for the To-do template and `vtAsk.js`. Tests only, not seen in Obsidian: Templater may not pass the helper on `tp.user.vtAsk` (if words are refused, that is why)
- **Rig snippet: a Summary table under the diagram** (lab kit). A rig note can have a `## Summary` table (any columns; the Rig template has `Item | Value` with pump contents, flow rate range, reactor volume). Alt+S → Rig puts it directly under the diagram at the cursor; the parts tables still go to the bottom section. A rig without one inserts nothing extra. New snippet token `{{rig-summary:key}}`. Review update… for the Rig snippet; Restore kit original on the Rig template for new rigs. Tests only, not seen in Obsidian; how the diagram looks in a PDF export is not checked
- **Rigs folder has a default, and rigs can be batch setups** (lab kit): the Rigs folder box shows `03 Lab Book/Rigs` greyed and uses it unless you type another, so the Rig template, New rig and Alt+S → Rig are on from the start. New part kind **Stirrer** (drawn on a dashed line to its vessel, like a Heater); a rig with one Reactor row and nothing feeding it draws without problems. The Rig snippet starts with an empty line (so the diagram draws when the note opens), leaves out a `Tubing` or `Control` line the rig does not have, and takes its section heading from the rig note's `Setup heading` property (default `Flow platform setup`). Snippet templates get `{{note-line:key.Name}}` and `{{#append "# Heading" from key.Property}}`. Tests only, not seen in Obsidian
- **New: the Rig snippet (Alt+S → Rig)** (lab kit). Review update… installs it. Pick a rig note: the cursor gets a link to the rig and a fixed copy of its diagram (it does not change when the rig note changes later), the note gets a `Rig` property, and the rig's `Tubing` and `Control` lines and its parts tables are copied under a `# Flow platform setup` heading at the bottom of the note (added when missing, appended below its content when present), as that experiment's record; fill in the per-run cells there. Without a Rigs folder it is not installed. Tests only, not seen in Obsidian
- **Snippet templates can pick a note, set a property and write under a heading** (for your own snippets; `docs/snippet-syntax.md`): a field with `suggest: notes` and `folder: rigsFolder` lists the notes of a Lab Kit folder; a `set:` header writes properties on the note you are in; `{{rig-diagram:key}}`, `{{rig-tables:key}}` and `{{note-prop:key.Name}}` read the picked note; `{{#append "# Heading"}}…{{/append}}` puts a part at the end of the note under that heading instead of at the cursor. No shipped snippet uses them yet. Tests only, not seen in Obsidian
- **New: a `rig` block draws a flow rig from its parts tables.** In a note with small tables that have an `ID` and a `Feeds` column (Pumps, Reactor line, Analysis), an empty ```` ```rig ```` block shows the flow diagram: one box per part, an arrow to each part it feeds, a heater on a dashed line to its reactor. It redraws when the tables change; a `Feeds` ID that does not exist, a repeated ID or a row without one is listed under the diagram. A diagram wider than the note scrolls sideways
- **New: Rigs folder, Rig template and the command New rig** (lab kit). Set **Rigs folder** in Settings → Lab Kit → Lab notebook (empty means `03 Lab Book/Rigs`, shown greyed like the Templates folder; Check setup's Fix creates the folder), then Review update… installs the **Rig template**: `Tubing` and `Control` (manual, or the software and its version) properties, a `rig` block and three example tables (Pumps, Reactor line, Analysis). **New rig** asks a name and makes the note in that folder; it does not need Templater. Tests only, not seen in Obsidian
- **Guide notes: no doubled title, and a link back to the How-tos index** (planning kit): Vault spec, How my vault works, Hotkeys, Setting up a computer and Set up ZotLit started with a heading that repeated the note's name under Obsidian's own title. The heading is gone and each note starts with a back link to the hub one folder up (the How-tos index). Tests only, not seen in Obsidian
- **The guide notes update with the kit** (planning kit): Vault spec, How my vault works, Hotkeys, Setting up a computer and Set up ZotLit were installed once and then left alone, so a rewritten guide never reached you unless you pressed Use kit version… on each. They now behave like the templates: a guide you have not edited is updated by **Update all safe files** / **Review update…** (your old copy goes to the backup folder); one you edited is never overwritten, it is offered as a merge in Review update…, or shown as a conflict to resolve. The homepage, the boards and the hub notes (Projects overview, Meetings, Knowledge index, How-tos index, Literature, Weekly review, Shopping list) stay yours and are still never updated. Tests only, not seen in Obsidian
