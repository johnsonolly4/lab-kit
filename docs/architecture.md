# Architecture: where things are

Moved from `CLAUDE.md` (Map) on 2026-10-07. Update this when a folder or entry file is added, moved or removed.

- `src/main.ts`: plugin entry, registers features
- `src/calc/`: formula engine (parse, evaluate, rewrite refs) + table renderer
- `src/chem/`: chemical database (notes in the user's folder, matching, `[[` suggest popup for calc cells; `src/frontmatter.ts` = shared property readers)
- `src/header/`: hazard table + data-folder button (replaces the Dataview scripts)
- `src/kit/`: built-in kits (managed files, merge, merge window, settings tab and the New lab entry / New chemical commands in `ui.ts`; `managed.ts` + `managed-ui.ts` = kit file state and the Review / Manage windows, `merge.ts` + `merge-ui.ts` = three-way merge and the Compare / Resolve window; `backups.ts` + `backups-ui.ts` = Clear old backups; `setup-check.ts` (pure: Check setup rows, `SETUP_PLUGINS`, folder templates) + `setup-check-ui.ts`; `hotkey-check.ts` (pure, `RECOMMENDED_HOTKEYS`, kept in step with the Hotkeys note by `tests/hotkeys-note.test.ts`) + `hotkey-check-ui.ts`; `board-colours.ts` = Colour board columns; `datafolder.ts` = data folder roots; `ensure-folder.ts`, `settings-box.ts` = small shared helpers; `obsidian-private.ts` = every use of Obsidian's and other plugins' undocumented settings, in one file; `starter.ts` = the new-vault starter; `icon-list.ts` + `icon-picker-ui.ts` = the Snippet icons picker; `paths.ts` = folders + saved state: `kit.kits.<id>` per kit, `kitLoad` migrates a v0.5.2 single-kit `data.json`, `planningFolders`; `folder-guard.ts` = the "folder not found" notice; `moved-folders.ts` (pure ranking) + `moved-folders-ui.ts` = Find moved folders; `tidy.ts` (pure: Tidy up notes scan, rules from each kit manifest's `migrations` plus code rules, before / after rows, report; plan `docs/plans/phase-7-tidy-notes.md`) + `tidy-ui.ts` = the split window and the two-step Change notes…; `tidy-hubs.ts` = the rule that brings hub pages up to the current template; `tidy-apply.ts` = carries out the ticked changes through an injected `TidyIO`: backup, replace properties, move, create a new note, change a Templater / Meta Bind setting through `obsidian-private.ts`); the meetings and missing-hub rules are code in `tidy.ts` `scan`, off unless `TidyContext.meetings` / `hubFolders` are set (planning kit on); `snippet-copy.ts` (pure, Make my own copy, plan `docs/plans/make-my-own-copy.md`): runs one snippet with a stub `tp` (defaults, else the example text of empty text fields; neutral note name) and writes the note under the name you give (default `<name> (mine).md`, then ` 2`, ` 3`…), never over an existing file; `isTokenTemplate` / `copyTokenTemplate` copy a token template as the file itself; `snippet-copy-ui.ts` = the Make my own copy button's action (name box, token template → file copy, else bundled `labSnippets.js` / `labMethods.js`, Notice); `snippet-template.ts` (pure, token templates, plan `docs/plans/snippet-token-templates.md`): `parseTemplate` (header + body; null = plain snippet), `defaultAnswers`, `fillTemplate`, `isCancelled`; the note and vault come in through `TemplateEnv`; `snippet-env.ts` (pure: the engine's `TemplateEnv` from the note text, `classFilter` for Chemical class suggestions, `chemicalClasses` for the New chemical pick list; `codeSources` / `codeFormParts` / `resolveCodes` for `suggest: codes`, mirroring `labSnippets.js`); `snippet-note.ts` (pure: the edits a token template makes outside the cursor, `set:` properties and `{{#append}}` parts under a heading), `snippet-run.ts` (`SnippetTemplates`, on the plugin as `plugin.snippets`: `meta(file)` for the Alt+S menu, `run(tp, file)` = parse with Obsidian's `parseYaml`, ask with `labForm`, fill; `Insert snippet.md` calls it)
- `src/planning/`: planning kit engine. `todo.ts` = to-do board rules (pure: stamps on drag / tick, roll-over); `engine.ts` = `TodoEngine` (events, timers, board tagging), started from `main.ts` only when the planning kit is on and installed; `actions.ts` = planning commands' rules (pure: shopping list text, archive cut-off, unique names, deck path); `ask.ts` = the text box (port of `vtAsk.js`) and the picker; `commands.ts` = `PlanningCommands` (fixed command IDs, plan `docs/plans/phase-4b-planning-commands.md`), registered under the same gate and kept as `plugin.planning`; folders from Settings → Planning folders (`KitData.planningFolders`). `lists.ts` = homepage list rules (pure, ported from the Dataview queries); `meetings.ts` = meeting series (pure: parse a series hub, next date for weekly / fortnightly / monthly / every N weeks, `once` for the One-off hub, "since" window, flagged to-dos, next-meetings card lines); `buttons.ts` = the kit's Meta Bind button templates (`PLANNING_BUTTONS`, read from `meta-bind-buttons.json` next to it); `progress.ts` = Checklist progress; `blocks.ts` = the `vault-card` / `vault-goto` / `vault-projects` blocks (tiles, hub and meeting top rows, project and meeting cards), registered at load (plan `docs/plans/phase-5-homepage-meetings.md`)
- `src/rig/`: rig notes. `parts.ts` = parts tables of a note to parts, connections and Mermaid flowchart text (pure; plan `docs/plans/rig-notes.md`); `render.ts` = the ```` ```rig ```` block: draws the diagram of its own note through Obsidian's Markdown renderer, redraws on edit
- `src/node.ts`: the only `require()` (Node/Electron modules, null on mobile) · `src/platform.ts`: `hasNode()` · `src/whatsnew.ts`: What's new popup
- `kits/<id>/`: one folder per built-in kit, each with its own `kit-manifest.json` (schema 2: `id`, version, files); every kit is embedded in `main.js` at build
  - `kits/lab/`: the lab kit: vault files it installs (`Templates/`, `Extras/scripts/`, `.obsidian/snippets/`, and `03 Lab Book/`, `05 Chemicals/` for the .base files, which go in the folder above the Lab notes / Chemical folder settings: roles `labBase`, `chemicalBase`, from `kitFolderRoles` in `src/kit/paths.ts`; a file with `needs` in the manifest is off while that setting is empty, `offIds` in `src/kit/managed.ts`)
  - `kits/planning/`: the planning kit (offered as a preview since Phase 6): homepage and planning notes (roles named after their top-level folder, `policy: keep`, except the guide notes in `07 How-tos/Obsidian`, which are updated like templates: `keepFiles` in `scripts/kit-manifest.mjs`; folder names in the files are rewritten from Settings → Planning folders through the manifest's `rewrite`), `Extras/Templates/` (+ `ZotLit/`; the button actions are plugin commands since Phase 4b, the ZotLit files only with the ZotLit plugin: `needs: "plugin:zotlit"`), `vtAsk.js` in `<user scripts>/vault/`, two CSS snippets; folders from `planningRoles` in `src/kit/paths.ts`. Source and what is held back: `docs/plans/phase-3-planning-files.md`
  - `kits/lab/Extras/scripts/templater/`: Templater scripts: `labSnippets.js` (the code snippets: solution, recipe, raft, nmr, gpc, dls, method, results; matrix, samples, timetable, column, rt and blank are token templates in `Templates/Snippets/` since Phase 4), `labMethods.js` (analysis methods + machines from the Methods folder; NMR/GPC/DLS built in), `labForm.js` (pop-up forms), `labPick.js` (Alt+S menu)
- `docs/`: `tutorial.md`, `snippet-syntax.md`, `changelog.md`, `obsidian-test-checklist.md`, `plans/`, `reference/` (saved Obsidian docs: read these, don't fetch)
- `tests/`: vitest; `tests/fixtures/` holds real experiment tables
- `scripts/`: `kit-manifest.mjs` regenerates every `kits/<id>/kit-manifest.json` (per-kit folder → role table in `CONFIG`) · `embed-kit.mjs` embeds all kits in `main.js` · `make-tidy-vault.mjs` (`npm run tidy-fixture`) copies `tests/fixtures/tidy-vault` + `tidy-vault-planning` into the gitignored `test-vault-tidy/` (`tests/tidy-planning-fixture.test.ts` scans the planning part) · `make-starter.mjs` (`npm run starter`) bundles `src/kit/starter.ts` (pure `buildStarter`: `.obsidian` settings, plugin list from `SETUP_PLUGINS`, Templater folders / folder templates / Alt+S from the kit manifests and `paths.ts`, contract folders, plugin install scripts) and writes `dist/starter/`; `tests/starter.test.ts` runs it plus both kits through `checkSetup`
- `.github/workflows/release.yml`: builds, attests and publishes a release on a pushed tag
- `test-vault/`: dev vault (only `Welcome.md` tracked; notes, kit copies and plugin build are gitignored)
- `dist/`, `legacy/`: gitignored (old kit package output, no longer built; old v0.3 `main.js`, never committed)
- `README.md`, `GETTING-STARTED.md` (user setup guide), `LICENSE` (MIT)
- `STATUS.md`: now / next / blockers · `BACKLOG.md`: feedback by version
